## Goal

Make `test/unit/` failures trustworthy and easy to act on. Today the `compile()` helper runs a hand-built TypeChecker → CodeGen pipeline that production never uses, except when a regex spots a Go-source stdlib import. On that fallback path a compiler crash is reported as an ordinary compile error, and warnings are always `[]`. Ten negative tests only check `errors.length > 0`, so a crash makes them pass. The runner also has gaps: no way to run one file or one test, no timeout (a hung async test hangs `npm test` forever), failure summaries that omit the file, and 82 of 138 test files that exit 0 when run directly even if tests fail.

This plan routes `compile()` through `compileFiles`, makes compile errors structured and keeps crashes as crashes, tightens the negative tests and enforces the rule mechanically, folds the six copy-pasted `assert*Output` helpers onto one runner, and adds file/name filtering, timeouts, file-qualified failure output and a correct standalone exit code.

**Done means:**
- `npm test` passes with ≥ 4,792 unit tests (the baseline at `d94568cd`) plus the new tests, and no existing test is deleted or weakened (the G2b tests keep their substrings and assert them on `errors` instead of a thrown error).
- `test/unit/helpers.js` no longer constructs `TypeChecker` or `CodeGen` (`grep -nE "new (TypeChecker|CodeGen)" test/unit/helpers.js` prints nothing). The six tests in Gap G2 and the nine in G2b pass on the production path, and a thrown non-compile exception propagates out of `compile()` (covered in `test/unit/compiler/test-helpers.test.js`).
- `test/unit/compiler/test-conventions.test.js` fails on any `assert(<x>.errors.length > 0)` / `assert(errors.length > 0)` under `test/unit/`, and the tree has none.
- Harness fixtures in `test/unit/fixtures/harness/` prove all of these via `test/unit/compiler/runner.test.js`:
  - `node test/unit/run.js <file>` runs only that file;
  - `TEST_GREP=<re>` runs only matching tests;
  - a hung async test fails after `TEST_TIMEOUT_MS`;
  - the failure summary prints `<file> › <name>`;
  - `node <failing>.test.js` exits 1 and prints the summary exactly once.
- `AGENTS.md` **Commands** documents single-file runs, `TEST_GREP` and `TEST_TIMEOUT_MS`.

## Approach

### 1. Architecture & Design Decisions
- **Structured errors from `compileFiles`** (`src/compiler.js`): at each throw site for user-code diagnostics (`:466` parse, `:472` mixed packages, `:499` conflicting targets, `:549` type errors), throw a `CompileError extends Error` whose `message` stays exactly as today (CLI output is unchanged) and whose `errors` field holds the individual error objects: the checker's `TypeCheckError`s as-is, the `ParseError`/`LexError` caught per file, or a single `Error` for the mixed-package and conflicting-target cases. Keeping the original objects keeps their `line`/`col`, which `checker-strictness-plan.md` Phase 1 relies on. Every other exception stays a plain `Error` or `TypeError`. `compileFiles` also returns `warnings: [...checker.warnings, ...codegen.warnings]` and keeps calling `log.warn`. A `CompileError` class is preferred over a property bag so `instanceof` separates diagnostics from crashes without matching on message text.
- **One `compile()` path** (`test/unit/helpers.js`): `compile(source, { fromFile, strict, target })` always calls `compileSourceFile`, with no up-front `Parser.parse()`. The file is written as `basename(fromFile)` (default `_dummy.go`) and `fromDir` is `dirname(resolve(fromFile))`, so `js:` `.d.ts` imports and fixture-relative packages resolve as they do today. `target` is passed as `forceTarget` only when given, so a `//gofront:target` directive still applies otherwise. The `{ js, errors, warnings }` result shape is kept. Parse and lex errors now come back in `errors` like type errors (one contract: diagnostics are returned, crashes are thrown), so the 7 G2b(a) tests switch from `assertThrows` to `assertErrorContains` with the same substring. `importsGoSourceStdlib` stays only for the `compileWasm` helper (G8).
- **Crash propagation**: `compileSourceFile` turns only a `CompileError` into `errors`; any other exception is rethrown, so the test fails and shows the stack.
- **Negative-test enforcement**: a convention test scans `test/unit/**/*.test.js` (fixtures excluded, as `discoverTestFiles` does) for the weak pattern. This is chosen over a Biome rule because Biome cannot express it and `scripts/check-layers.js` is about `src/`.
- **Output assertions**: a single `runProgram(source, { target, natives, stdlibRoot })` returns stdout, plus `assertOutput(source, expected, { targets, natives, stdlibRoot })` that labels mismatches `<label> (natives on|off)` using one `firstDiff(expected, got)` function. The label is `js` for the JS side of `both` (as `assertFourWay` prints today, which the G9 self-tests assert), `wasm` for `wasm`, and `js package` for `js`. The six existing names become one-line wrappers, so none of the 85 calling files change.
- **Runner**:
  - `run.js` accepts file paths (relative to cwd or `test/unit/`; unknown path is an error, exit 2) and `--grep <re>`, which also comes from `TEST_GREP` and is passed to workers.
  - `helpers.test()` skips non-matching names and counts them as `skipped`, which the summary prints.
  - Async tests race a `TEST_TIMEOUT_MS` timer (default 120,000; the slowest single test today is under 10 s). The timer is cleared when the test settles. An uncleared timer would keep a directly run file alive for the full timeout before `beforeExit` fires.
  - `run.js` terminates a worker whose file runs past `TEST_FILE_TIMEOUT_MS` (default 900,000, about 6× the slowest file under full load), records `<file> › timed out`, and starts a fresh worker, reusing the existing `workerDied` path.
  - Failures carry `file`, and the summary prints `<file> › <name>`.
- **Standalone exit code**: on the first `test()` call on the main thread (`isMainThread`), `helpers.js` registers a one-shot `process.on("beforeExit")` hook. The hook awaits pending tests, prints the summary and sets `process.exitCode`. When it fires, it does nothing if `globalThis.__GOFRONT_TEST_RUNNER` is set (`run.js` sets it for `TEST_PARALLEL=0`; it has to be checked at fire time, because `run.js` sets it only after its static `helpers.js` import has evaluated, G11) or if `summarize()` has already run. Registering lazily keeps the perf scripts that import `compile()` but never call `test()` silent. Files with the existing footer call `process.exit()`, which skips `beforeExit`. The 2 bare `summarize()` callers are covered by the already-summarized check, so nothing prints twice.

### 2. Invariants & Safety Bounds
- CLI output for compile errors is byte-identical: `CompileError.message` equals today's joined string, checked by the existing `cli/cli*.test.js` error-output tests.
- No change to generated JS or WASM. `src/` changes are limited to `src/compiler.js`, and `npm run check:layers` stays green.
- `npm test` with no arguments runs exactly the same file set as today (`TEST_FILES`), and the test count does not drop.
- The `test/perf/` scripts that import `compile()` keep passing on the production path (`zero-alloc.js` is part of `npm test`), and print no harness summary.
- The worker protocol stays backward compatible: messages gain `skipped` and per-failure `file`, and no field is removed.

### 3. Edge Cases & Error Handling
- `compile()` callers that pass `fromFile` pointing at a real fixture (15 sites): if the temp file used the fixture's own name next to the fixture it would shadow it, but the temp file lives in a fresh temp dir and only `fromDir` points at the fixture dir. `compileFiles` must resolve imports from `fromDir`, not from the file's directory, which the `options.fromDir` override at `src/compiler.js:440` already does. G2 confirms it.
- Multi-error sources: `CompileError.errors` keeps one entry per checker error, so "two independent undefined vars produce 2 errors" holds.
- Warnings on stderr: the production path still `log.warn`s every warning, so a few more warning lines appear in the worker-captured stderr (31 vs 22 in the 2026-11-13 probe). That is accepted. Returning warnings doesn't change what the CLI prints.
- `TEST_GREP` with no match in a file: the file reports 0 run and N skipped, and the run exits 0 only if at least one test ran overall. Otherwise it exits 1 with "no tests matched", so a typo'd filter isn't mistaken for a pass.
- A timed-out async test keeps running in the background. Its later output and late settlement must not be counted again, so the slot is filled once by a guard flag.
- A sync infinite loop can't be stopped in-thread. The per-file watchdog covers it.
- `TEST_PARALLEL=0` keeps working, sets the runner flag, and honours file args and grep.
