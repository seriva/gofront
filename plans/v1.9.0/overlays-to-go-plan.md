# Stdlib Overlays to Go — Design Plan

**Version:** v1.9.0  
**Status:** In Progress  
**Base branch:** `main`  
**Related:** [`compiler-shrinking-plan.md`](compiler-shrinking-plan.md) (prerequisite: its Phase 4 makes per-package generated Go run on every target), [`stdlib-in-go-plan.md`](stdlib-in-go-plan.md), [`follow-ups-2026-11-03-plan.md`](follow-ups-2026-11-03-plan.md), [`../v2.0.0/native-go-engine.md`](../v2.0.0/native-go-engine.md)  
**Release note:** `fmt`, `testing`, `os`, `unicode`, `regexp`, `crypto/rand`, the timer half of `time` and the `gom` DOM builders now compile from Go source, so WebAssembly packages format values and run their tests inside the module instead of calling back into JavaScript. `errors.As` honours custom `As` methods on both targets, `os.File.WriteString` reports byte counts, and importing a JavaScript-only package such as `regexp` from a WebAssembly package reports a clear error instead of crashing the compiler.

---

## Goal

Remove the last hand-written stdlib machinery from `src/` after [`compiler-shrinking-plan.md`](compiler-shrinking-plan.md) lands: the `fmt` engine (JS `__sprintf` + WASM externref marshalling that round-trips every `Sprintf` through the host), the host-object `testing` protocol, the backend-specific `errors.As`, and the six small overlays (`os`, `unicode`, `crypto/rand`, `time.Sleep`/`AfterFunc`/`Timer`, `regexp`, `gom`). Each becomes ordinary Go in `stdlib/` plus, where the host must be reached, a body-less `//gofront:intrinsic` with a one-line body per backend. Compile-time type knowledge that Go's `fmt` gets from reflection comes from a per-package generated Go file, the same technique `src/lower/json-codecs.js` already uses. Every line moved out of `src/` is a line the v2.0 native engine does not have to port, and `fmt`/`testing` are the two pockets that would cost the most to port.

**Done means:**
- `src/` shrinks by **≥ 5,000 net lines** against the tree at the end of `compiler-shrinking-plan.md` (measured with `find src -name '*.js' -exec cat {} + | wc -l`; today 71,587 — the 61,515 baseline quoted in `compiler-shrinking-plan.md` predates the follow-up fixes and must be re-measured there — of which ≈ 6,670 are attributable to the subsystems below), and these files are deleted: `src/backend/js/fmt-runtime.js`, `src/backend/js/stdlib/{fmt,testing,errors,os,unicode,regexp,gom,time,cryptorand}.js`, `src/backend/wasm/stdlib/pure.js`, `src/backend/shared/errorf.js`.
- `STDLIB_PACKAGES` in `src/typechecker/types.js` contains only `gofront/shared`, `gofront/simd` and `encoding/json`; `src/typechecker/stdlib/{core,extended}.js` define no `fmt`, `errors`, `os`, `unicode`, `time`, `testing`, `context`, `rand`, `regexp` or `gom` member, and `WASM_STDLIB_MEMBERS` has no row for them.
- `fmt` on `js`, `wasm` and `both` targets passes `test/unit/builtins/fmt-verbs.test.js` (60), `test/unit/builtins/fmt-stringer.test.js` (44), `test/unit/wasm/fmt-any.test.js` (32) and `test/unit/stdlib/fmt.test.js` unchanged except for GoFront-specific `%p` wording, and `node test/perf/fmt-bench.js` reports JS ≤ 2.0× and WASM ≤ 1.0× the baselines recorded in Task 4.1.
- `gofront test` passes on every `example/*` package (JS and WASM) with `*testing.T` a Go struct: `test/unit/cli/test-runner.test.js`, `test/unit/cli/cli-core.test.js` and `example/preact/src/fetch_test.go` (async tests) stay green; `npm run test:e2e` passes.
- `errors.As` with a target type that defines `As(any) bool`, `os.Stdout.WriteString("é\n")` returning `3`, and `import "regexp"` in a wasm package producing `package 'regexp' is only available in js packages` pass four-way (`assertFourWay`) or as negative `assertErrorContains` cases in `test/unit/stdlib/errors.test.js`, `test/unit/stdlib/io.test.js` and `test/unit/compiler/targets.test.js`.
- All quality gates pass: `npm test`, `npm run check`, `npm run test:e2e`.

## Approach

### 1. Architecture & Design Decisions

#### A. Generated-Go spine (shared by `errors.As` and `fmt`)
- **One generated file per package, every target.** Generalise `checkJsonCodecs` (`src/link/stdlib.js`) into `checkGeneratedGo(programs, checker, …)`: a list of generators (`src/lower/json-codecs.js`, new `src/lower/errors-as.js`, new `src/lower/fmt-formatters.js`) each returns `{ source, imports, diagnostics }` fragments; the spine concatenates them into `gofront_gen.go`, parses, imports and checks it as one more file of the package (exactly today's `json_codecs.go` path), and `lowerStdlibRefs` (`src/lower/stdlib-refs.js` after the sibling plan) rewrites any `SelectorExpr` carrying the generalised `_genEntry` marker (today `_jsonGen`) into an `Ident` call of the generated function.
- **Generated code is ordinary Go.** No checker rule is relaxed for generated files: GoFront has no cross-package unexported-field check for user structs (the only such check is the `strings.`/`bytes.` `_field` guard at `src/typechecker/resolve.js:913-923`, which the sibling plan removes with `strings.Builder`), so a generated formatter in `main` can read `lib.T`'s unexported fields as `%v` requires. Go's *visibility* rule for `fmt` is a formatting rule instead (unexported fields skip `Stringer`/`GoStringer`, see §E).
- **Naming:** `gfe_<pkg>_as_<n>` (errors), `gff_<pkg>_value` / `gff_<pkg>_type` (fmt), keeping json's `gfj_<pkg>_` prefix. Rejected alternative: emitting typed AST directly from `src/lower/` — the backends read checker-attached `_type` on every node, so generated *source* that goes through the checker is the only path that cannot drift.

#### B. `errors.As` as a generated function (≈ 370 lines removed)
- Per call site `errors.As(err, &x)` with static target type `*T`, generate
  ```go
  func gfe_main_as_0(err error, target *T) bool {
      for err != nil {
          if v, ok := err.(T); ok { *target = v; return true }           // omitted when T is an interface: `if v, ok := err.(I)`
          if a, ok := err.(interface{ As(any) bool }); ok && a.As(target) { return true }
          switch u := err.(type) {
          case interface{ Unwrap() error }: err = u.Unwrap()
          case interface{ Unwrap() []error }:
              for _, e := range u.Unwrap() { if gfe_main_as_0(e, target) { return true } }
              return false
          default: return false
          }
      }
      return false
  }
  ```

#### E. `fmt` in `stdlib/fmt/` (≈ 3,890 lines removed; ≈ 1,180 Go + ≈ 550 generator added)
- **Package shape** (`both`): `print.go` — `pp` printer (`buf []byte`, `fmt` flags, arg index, `%!verb(type=value)`/`%!(EXTRA …)`/`%!(MISSING)`/`%!(BADINDEX)` forms, `*` width/precision, `%[n]`), `Sprint*`/`Fprint*`/`Print*`/`Append*`/`Errorf` (`wrapError`/`wrapErrors` with `Unwrap`), `Stringer`, `GoStringer`; `format.go` — padding, `fmtBoolean`, `fmtInteger` (`%d %b %o %O %x %X %c %q %U`), `fmtFloat` via `strconv.FormatFloat` (`%e %E %f %F %g %G`, `#` and `+` flags), `fmtS`/`fmtQ`/`fmtBx` for strings and `[]byte`, complex as `(r+ii)`; ported from Go's `fmt/format.go` and `print.go` minus reflection. `fmt` imports only `errors`, `io`, `os`, `strconv`, `unicode/utf8`, `slices` and `internal/fmtrt` — none of which import `fmt` (`encoding/hex` and `internal/jsonrt` import `fmt`, not the reverse).
- **Two kinds of operand.** Go's `fmt` learns every operand's type through reflection; GoFront's `fmt` learns it in two ways, both resolved at compile time by `src/lower/fmt-formatters.js`:
  1. **Statically typed operands → per-call-site wrapper (`_genEntry`).** For every `fmt` call whose operand list has at least one operand with a non-interface static type that JS cannot recover from the boxed value (any numeric kind other than `int`, `int64`-vs-`uint64`, named basics, structs, pointers, slices, arrays, maps, funcs, complex; also any value type whose `String`/`Error`/`GoString` has a pointer receiver), the generator emits a wrapper keyed by `(fn, static-signature)` and redirects the call to it with the json `_genEntry` marker:
     ```go
     func gff_main_Sprintf_s_f64_P(format string, a0 float64, a1 P) string {
         return fmt.Sprintf(format, fmtrt.Arg{V: a0, K: fmtrt.KFloat64, T: "float64"},
                                    fmtrt.Arg{V: a1, F: gff_main_fmt_P, T: "main.P"})
     }
     ```
     `fmtrt.Arg` carries the value, a basic kind (`K`) or a generated formatter function (`F`), and the Go type string for `%T`/`%#v`. `printArg` unwraps `Arg` first and never type-switches on it; `int`, `string`, `bool`, `error` and value-receiver `Stringer` operands are passed bare (their JS representation is unambiguous). A `...any` spread and interface-typed operands are passed bare too. This is today's `__ft(value, descriptor)` with a compiled function in place of the descriptor and the same decision table as `_fmtArgJs`; it also gives `%T`/`%#v` exact names without any runtime type name, and lets static operands skip the closed-world switch entirely.
  2. **Interface-typed operands (and `any` fields/elements) → registered closed-world switch.** `stdlib/internal/fmtrt/fmtrt.go` holds the registry (`Formatter func(p *Printer, v any, verb rune) bool`, `TypeName func(v any) (string, bool)`, `Register(f, t)`) and the `Printer` state `fmt` formats into, mirroring `internal/jsonrt`. The generator emits `gff_<pkg>_value` (a `switch v := a.(type)` over json's enumeration — `programTypes()`, package-level named types, pointer-to-named, `SHARED_REPR` rules) and `gff_<pkg>_type`, registered by a `var _ = fmtrt.Register(...)` initialiser. Registration keeps `fmt` free of GoFront-only exports and covers values boxed in one package and printed in another. Rejected: a `fmt_value` intrinsic emitted by the backends (≈ 1,000 lines of emitter per backend); exporting the registry from `fmt`; changing how the JS backend boxes basics into `any` (every interface value would pay for `fmt`).
- **Per-type formatters** (`gff_<pkg>_fmt_<T>`, one per type reachable from a wrapper or the switch) emit `{f1 f2}` / `{Name:f1 …}` for `%+v` / `main.P{X:1, Y:2}` for `%#v`, `[a b]`, `map[k:v]` with keys sorted by Go's `fmtsort` order for basic key kinds (insertion order otherwise), `&{…}` for a depth-0 pointer-to-struct and `0xN` (`fmt_ptr_id`) for deeper pointers, `<nil>` for nil pointers/maps/slices. Field and element types are static, so nested numeric kinds and method sets are exact: an **exported** field or any element goes through `handleMethods` (`Stringer`/`GoStringer`/`error`); an **unexported** field skips `Stringer`/`GoStringer` but still prints an `error` value's message, exactly Go's rule (`fmt-stringer.test.js:217`); a value field whose methods have pointer receivers gets no method dispatch. A field or element typed `any`/interface goes through the registered switch.
- **Generation gate (zero-unused-cost).** Wrappers exist only for call sites that need them; the registered switch is generated only for a package in which at least one `fmt` operand, field or element has an interface or `any` static type or a `...any` spread — the condition `prescan.js:117-158` uses today for `__any_fmt`. Packages that only format basics, Stringers and statically typed composites get wrappers and per-type formatters (reachability-pruned) but no registry root. Within a gated package the enumeration is json's; nothing is added for other packages' types unless they appear in this package's expressions. A value that reaches the switch with no case falls back to `fmtrt`'s fallback (see Edge Cases), never to a crash.
- **`%p`:** `fmt_ptr_id(any) uint64` intrinsic returns the stable per-object id today's docs describe (JS `WeakMap` counter; WASM `extern.convert_any` + the same `WeakMap` on the host — WasmGC objects keep identity across the boundary). Non-pointer operands print `%!p(T=v)` in Go.
- **Performance:** new `test/perf/fmt-bench.js` (100k mixed `Sprintf` calls: ints, floats, strings, `%v` struct, `%q`, `Stringer`) records JS and WASM baselines before the switch; gates JS ≤ 2.0× (hand-written `__sprintf` → compiled Go) and WASM ≤ 1.0× (no host crossing any more). Byte growth uses the amortised `HELPER_APPEND` from the sibling plan.
- **Removal:** JS `fmt.js`, `fmt-runtime.js`, `HELPER_SPRINTF/SPRINT/IFD`, `__ft` descriptors and `__pr` class metadata (`type-info.js`, `expressions.js`, `_genFmtClassMeta`; `fmt-stringer.test.js:271-273` becomes a behavioural assertion), `src/backend/shared/errorf.js` (delete) and `src/backend/shared/fmt-types.js` trimmed to `goTypeName` for `monomorph.js`; WASM externref family, `__any_fmt`/`__any_fmt_key` synthetics, `_emitArgBuffer`, `emitFmtCall`, `fmt_*` imports and `${P}stdlib_fmt`, prescan fmt detection, and the `ERROR_STRUCT`/`__mk_wrap_errors`/`hasErrorType` synthetic helpers that only `Errorf`/`errors` emitters used (those backing panic/recover and host-error conversion in `boundary.js:2092-2096` stay; Task 6.1 audits each reference); typechecker `fmt` overlay and `fmt.Stringer` (now Go). `fmt` leaves `STDLIB_PACKAGES`/`WASM_STDLIB_MEMBERS`.

### 3. Edge Cases & Error Handling

- **`fmt` closed world:** `SHARED_REPR` ambiguity (`[2]byte` vs `[2]int32` in an interface) resolves to the literal-registered type exactly as `json-codecs.js` and today's `__any_fmt` do; a `[]Celsius` with `String()` elements formats through its generated case, replacing the `__ifd` descriptor. Every registered formatter returns `false` for a type it does not know so the next package's formatter is tried; only when none matches does the fallback below apply.
- **Registration order:** `var _ = fmtrt.Register(...)` in the generated file must run before any user package-level initializer that formats a struct; `test/unit/builtins/fmt-stringer.test.js` gets a `var s = fmt.Sprint(P{1})` package-level case on all targets. If `init-order.js` cannot order it, the generator emits the registration as the first statement of a generated `init()` and the checker's init ordering places generated files first.
- **Gate misses:** a composite value that reaches `fmt` only through an `any` produced in a package that did not pass the gate (no fmt call with a non-basic operand there) has no generated case; `fmtrt` prints `<unknown T>`-free Go-compatible fallbacks where it can (`<nil>` for nil, `%!v(unknown)` otherwise) and never panics. The 136 existing fmt cases must never hit this path; `test/unit/wasm/fmt-any.test.js` gets one explicit cross-package case (struct built in `lib`, printed via `any` in `main`, `lib` has no fmt call) that must print correctly because `main`'s enumeration sees `lib.T` in its expressions.
- **`%p` / nested pointers:** depth-0 `*struct` prints `&{…}`; deeper pointers, funcs and `%p` print `0x<id>` via `fmt_ptr_id`; `%p` of a non-pointer prints `%!p(int=5)`; nil prints `0x0`. The existing `docs/go-compatibility.md` `%p` row stays accurate.
- **`Errorf("%w")`:** one `%w` → `*wrapError`, several → `*wrapErrors` (`Unwrap() []error`), `%w` with a non-error operand → `%!w(type=value)` and a plain `errors.New`-style error, as Go.
- **`errors.As` edge cases (all four-way):** interface target, pointer-to-struct target, struct-value target, named scalar error type, typed-nil `*T` inside the chain, `errors.Join` trees, custom `As` method, nil `err` → `false`, nil target → panic `errors: target cannot be nil`, non-pointer target → compile error.
- **Testing semantics preserved:** `t.Fatal` under a user `recover()` still marks `FAIL` (flag set before the sentinel panic; execution may continue as today); sentinel panics never escape `tRunner`; a panic inside `Cleanup` fails the test; `Skip` after `Error` reports `FAIL`; subtest names `Parent/sub` with `-run Parent/sub` matching via `testing_match` on each level; benchmark `b.Loop()` stops at the target duration or 1e9 iterations; `b.N` is set per round as today. `TestMain` + async tests → build error with the fix hint; async subtests inside a sync top-level test are settled by the driver before the package summary.
- **js-only stdlib from wasm:** `import "regexp"` / `gom.` in a `wasm` or `both` package → typechecker diagnostic with blocker category (`package 'regexp' is only available in js packages`; `gom` keeps its wording), never an emitter throw (fixes P8). `time.Sleep`/`AfterFunc`/`Timer` from wasm → `'time.Sleep' is only available in js packages`; `test/unit/compiler/targets.test.js` asserts the new texts.
- **`os.Stdout` writes:** `WriteString("é\n")` returns `3`; partial-line output is buffered until `\n` in browsers (no `process.stdout`) exactly as `__os_write` does; `Stderr` goes to `console.error`; `Read` returns `0, io.EOF`; `Exit` inside `gofront test` is never called by the Go `testing` package (the driver returns the code).
- **`gom`/`.templ`:** `gom.Mount(sel, node, refs...)` forwards `refs[0]` (or `nil`) as the plain second `Mount` argument so templ's `___refs[key] = el` sees the map itself, never a `{ __sp }` spread wrapper; `gom.Map` returns a `Group` whose JS wrapper carries `_items` for templ `for` forms; `Map` over `[]string` and `[]int` both infer `T`; a `js` program using `gom.` without an import gets the auto-import and no "undefined: gom" error; a `both` program gets the existing blocker.
- **JS numeric kinds and method sets in `fmt`:** `fmt.Sprintf("%T %v %d", 3.0, float32(2), uint8(200))` prints `float64 2 200` on JS because each operand travels in an `fmtrt.Arg` with its static kind; `fmt.Println(Counter{5})` with `func (*Counter) String()` prints `{5}` and `fmt.Println(&c)` prints `counter` (no `__pr` needed); a `float64` stored in a user `any` and then printed keeps today's documented JS behaviour (`%T` reports `int` for integral values) because no static type exists — `docs/go-compatibility.md` gets a row for it; `int64`/`uint64` BigInts are distinguished by `Arg.K` when static, by sign heuristics otherwise.
- **Intrinsic validation:** `INTRINSICS` signature strings cover `async` (`time_sleep`) and func-typed parameters (`testing_call`); `_checkIntrinsic` rejects a body or a mismatched signature as today.

- Phase 4 as built (deviations, for Phase 5/6): `fmtrt` holds data, not a printer. `Arg` describes an operand (kind, value in a typed field, closures for fields/elements/entries/pointee, `Err`/`Str`/`GoStr` set from the static method set); `fmt` owns all printing and `fmtrt` has only `Arg`, `Register(key, f)`, `Lookup`, `PtrID`; there is no `fmtrt.Printer`. Generated per package: `gff_<pkg>_<Fn>_<n>` wrappers (statically typed params, non-variadic, redirect via `_genEntry`, `call.func._type` replaced), `gff_<pkg>_a<n>` builders (one per composite type), `gff_<pkg>_value` + `gff_<pkg>_ensure` (registered lazily by every wrapper of a package with a lookup, so package-level initialisers that print work; `Register` dedupes by key). Bare operands: `string`, `bool`, `wasm`-only `int`, interfaces, named struct/scalar types whose value method set has `String`/`Error` (not string-kinded, slices, maps). JS wraps `int` (a JS number is exact only to 2^53, plan assumed bare). Type-parameter operands are boxed by the JS backend through the type argument (`_boxTypeParam`, `__ti` `.b`/`.fb`) because they cannot be described statically. Local (function-scope) types are spelled by name: the checker type table resolves them in the generated file. Unknown dynamic values print `<nil>` for `%v` (nil func in `any` has no type to look up). Parsed ASTs are cached across builds: the generator clears stale `_genEntry` first. Known gaps in `follow-ups.md`. Phase 5 must: add the `f` family to `FMT_PRINT_FUNCS`/`PRINT_FUNCS` and make interface operands of any interface type (not only `any`) trigger the lookup, because `%d`/`%+v` call no methods; keep the `isString` bare-operand rule when widening bare named types.
