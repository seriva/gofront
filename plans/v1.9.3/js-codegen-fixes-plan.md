# v1.9.3 JS Codegen Fixes — Design Plan

**Version:** v1.9.3  
**Status:** Draft  
**Base branch:** main  
**Related:** [`../v2.0.0/checker-strictness-plan.md`](../v2.0.0/checker-strictness-plan.md) (the breaking half of the same 2026-11-13 review), [`../v2.0.0/web-platform-evolution-plan.md`](../v2.0.0/web-platform-evolution-plan.md) (Phase 7 retypes `BROWSER_GLOBALS` without changing its membership; Task 3.1 owns import cycles; Task 4.5 owns duplicate runtime helpers).  
**Release note:** Functions, variables, local types, struct fields and templ components named after JavaScript built-ins or runtime properties (`Map`, `BigInt`, `NaN`, `__clone`) no longer break the bundle, and side effects in divisors, shift counts and multiple assignments run once and in Go's order. Anonymous structs copy their array and struct fields and work in literals that omit the type and as generic type arguments, and in WebAssembly `recover()` returns the panic value with its type and slice-bounds panics name the bounds as Go does.  

---

## Goal

Fix the miscompiles of valid Go found in the 2026-11-13 review and the follow-up probes. Every item compiles today and then crashes or prints a wrong result at run time. No fix rejects a program that compiles today, so this is a patch release that does not wait for v2.0.0.

**Done means:**
- Every repro in *Verified Gaps* (C1–C12) prints Go 1.26's output on `js`, `both` and `wasm` (except the cases listed as `Excluded: runtime / platform`). Each repro is a test in `test/unit/types/shadowing.test.js`, `test/unit/compiler/strict-mode.test.js`, `test/unit/language/codegen-regressions.test.js`, `test/unit/language/value-semantics.test.js`, `test/unit/wasm/defer_recover.test.js`, `test/unit/compiler/strict-panics.test.js`, `test/unit/compiler/local-type-shadow.test.js`, `test/unit/language/structs.test.js` or `test/unit/wasm/generics.test.js`.
- `test/unit/compiler/js-globals.test.js` fails when a runtime helper, inline template or facade template references a host global missing from the rename set (C1). It is modelled on `test/unit/compiler/natives.test.js`.
- `npm test` passes with `test/perf/zero-alloc.js`, `bce-mathx.js` and `bundle-size.js` unchanged (`bundle-size.baseline.json` not edited).
- `docs/go-compatibility.md` (*Names that shadow JS globals*, `defer`/`recover()` row, runtime-panics row) describes the new behaviour.

## Approach

### 1. Architecture & Design Decisions
- **C1–C2, one rename set:** add `JS_RESERVED_GLOBALS` and `shadowsJsGlobal(name)` (`BROWSER_GLOBALS.has(name) || JS_RESERVED_GLOBALS.has(name)`) to `src/typechecker/types.js`. The backends already import from there, and the checker cannot import the backend. The set holds the ES globals generated code or hosts rely on: `Infinity NaN undefined globalThis Map Set WeakMap WeakSet WeakRef BigInt Proxy Reflect Function Iterator ArrayBuffer DataView` plus every typed-array constructor, `TypeError RangeError SyntaxError ReferenceError WebAssembly process global escape queueMicrotask structuredClone`, and every name the registry test finds.
  - **Decision (open in the outline):** keep `BROWSER_GLOBALS` and `JS_RESERVED_GLOBALS` as two sets combined only in the rename check, not one merged set. `BROWSER_GLOBALS` stays the checker's predeclared table, which web plan Phase 7 retypes. The new set is rename-only and is never predeclared, so it cannot change what compiles.
  - `JS_BUILTIN_CLASSES` (type-name rejection) is not widened: rejecting more names is breaking. It moves to `types.js`, and the registry test asserts it is a subset of the rename set.
  - Every rename-side check of `BROWSER_GLOBALS` switches to `shadowsJsGlobal`: the checker's `_shadowsGlobal` mark (`src/typechecker/expressions.js:258`), `jsBindingName` (`src/backend/js/index.js:134`), the bundled-package selector (`src/backend/js/expressions.js:1330`) and `facadeName` (`src/backend/wasm/boundary.js:2236`). `TemplDecl`/`CssDecl` declaration names get `jsBindingName`. The `wasm`-target "not available" error (`typechecker/expressions.js:270`) and `_calleeIsGoVariadic` (`expressions.js:1584`) keep `BROWSER_GLOBALS`.
  - Rejected: capturing intrinsics in a prelude (`const __Map = Map`). It makes bundles bigger and every helper would need rewriting.
- **Renamed exports stay renamed on every target (outline edge case resolved):** the `wasm`/`both` facade already exports `Array$` (documented). Go identifiers cannot contain `$`, and generated names never end in `$` after a user-chosen stem (`__p${n}` → `__p1`), so the result cannot collide. It applies through `_renameIdentNode` to declarations and references alike, as `JS_RESERVED` does today. Struct keys and fields are excluded (`_isStructKey`, selectors; fields are deferred). Identifiers synthesised by lowering (`__yield_p<i>`, `src/lower/range.js:28`) carry a marker and are exempt.
- **C4, evaluate once, left first:** `_genStrictBinary` keeps today's text when neither operand AST has a call (`_hasCallExpr`, `src/backend/js/expressions.js:2945`), so hot loops, BCE and the zero-allocation gate are unchanged. Otherwise it emits `((__a, __b) => <template on __a, __b>)(l, r)`, the form `_gen64BitBinary` already uses. Arguments are evaluated left then right, once each, and before the body, so the "count ≥ width" branch no longer skips the left operand. `await`/`yield` inside an operand is fine because the arguments are evaluated in the enclosing function. `_genStrictCompound` takes the right-hand AST node. With a call, it binds the target's object/key temporaries first, then `const __r<n> = <rhs>;`, matching Go's order (target operands, then the value).
- **C5, field-wise copies:** `_cloneJs` for an anonymous struct (no class) with at least one array or struct field (recursively) emits `((__v) => ({ F: <_cloneJs(F, "__v.F")>, … }))(js)`, with fields from the checker type in declaration order. Anonymous structs without aggregate fields keep `__sclone` (byte-identical). `_genStructClone` calls `_cloneJs`, so `v06` is fixed by the same change. `__vclone(z, x)` uses the zero value `z()` as a shape: it recurses into a field or element only where the zero holds an array or a plain object. Pointer, slice, map, func and interface fields have `null`/non-object zeros and stay shared, and class instances keep `__clone()`.
  - Rejected: synthesising a class per anonymous struct type. It changes the output of every anonymous struct, and `fmt`, `==` and JSON assume plain objects.
- **C9:** `_genImplicitCompositeLit` dispatches to `_genAnonStructLit` when the literal type (pointer-stripped for an elided `&`) has an anonymous struct underlying.
- **C6, Go's assignment phase 1:** when an assignment has two or more targets and any right-hand side or any target operand contains a call, every non-constant target operand is evaluated into a temporary in source order before the right-hand sides. Target operands are the index base and index, the selector base through a pointer, and the `*p` operand. Struct/array-valued bases recurse as today. Without calls, the output is today's code. ### 2. Invariants & Safety Bounds
- A program that compiles and runs correctly on 1.9.2 prints the same output. The only intended difference visible from JS is the `$` suffix on bindings named after a global in the new set, or starting with `__`.
- Emitted JS for programs without the affected names, without calls inside strict `/ % << >>` operands or multi-assignment targets, and without anonymous structs that have aggregate fields is byte-identical to 1.9.2. Bundle-size budgets are unchanged.
- The zero-allocation, BCE and bundle-size perf gates pass, and no new allocation appears on hot paths: binding happens only when an operand has a call.
- `JS_BUILTIN_CLASSES` does not grow: no new type declaration is rejected.

### 3. Edge Cases & Error Handling
- **Cross-package and dot imports:** `util.Map()`, `import . "./util"` then `Map()`, and the `wasm` facade must all use the suffixed binding (as the `Array$` tests in `test/unit/types/shadowing.test.js` do).
- **Variadic user functions:** `func Map(xs ...int)` called as `Map(ys...)` must still pass the slice marker (`_calleeIsGoVariadic` must treat a renamed user function as Go-compiled).
- **Every local binding form:** a range key/value, type-switch binding, closure parameter, `for` init and named result named `NaN`/`BigInt` are renamed in their declaration and every reference.
- **A name that is both a Go builtin and a JS global:** none exists today (the builtins are `len append …`). The registry test fails if one appears, because `_renameIdentNode` skips `builtin`-typed identifiers.
- **Import alias or package directory named after a global** (`import Map "./util"`): namespaces are never renamed (`t.kind !== "namespace"`; existing tests for `console`).
- **C4:** the BigInt path (`_gen64BitBinary`) already binds and is not changed. A constant divisor keeps today's text (no call). `__tar` (type parameters) and `float32` already evaluate once.
- **C5:** an anonymous struct with a pointer field (`Ptr *P`) keeps sharing the pointee (`v04`). A slice field keeps sharing the backing array (`v04`).
- **C8:** `wasm` 64-bit indexes are converted to `i32` before the check today, and the message must print the original value for negative or large indexes (`[-1:]`).
- **C10:** a local `type Map` and a value `Map` in the same function: `renameLocalTypes` already handles a value of the same name (`declaresValue`). A local type named after a built-in inside a generic function. A `wasm` package type `WeakMap` that another package also declares (both renames must compose, not produce `WeakMap$$util$$util`).
- **C11:** promoted fields and methods through embedding (`_promotedPath`), method values (`x.__clone` bound), interface dispatch to a `__` method, and struct keys of a map (`__sk`) must all use the suffixed name.
- **C12:** two different anonymous struct type arguments of the same generic need distinct instances. The same anonymous struct written twice (or through an alias) must share one instance.
