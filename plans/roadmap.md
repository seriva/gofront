# GoFront Roadmap

GoFront's guiding principle is **no runtime** — features that need a scheduler, runtime
type descriptors, or raw memory access are out of scope.

Each release has a subfolder in `plans/` containing design documents for the planned
features (e.g. `plans/v1.8.0/`).

## v2.0.0

**Theme: Go-faithful compiler and a typed web platform (Draft, breaking).** Turn GoFront into a complete web application toolchain without giving up the pure Node.js ESM compiler or the **no runtime** principle (no scheduler, no runtime reflection, no garbage-collected runtime threads): compile-time asset embedding, fast incremental `gofront dev` rebuilds, whole-program dead-code elimination, typed web APIs and reactive `gom` signals in `.templ`; a checker and backends that follow the Go spec (reject the invalid Go 1.x accepted, keep value semantics on every target); and a hardened unit test harness underneath. Backward compatibility is not a goal (user decision 2026-11-13): it may break source that compiled on 1.x when that removes a class of problem, and the 2.0.0 changelog gathers every **Breaking:** entry into one migration section. Motivating consumer: SimpleFPS (`seriva/simplefps`).

**Order (2026-11-17).** Done: harness → assignment semantics → checker strictness. Then three lanes that touch different code and can run in parallel:
- *Checker and compiler:* checker Go rules → checker operand rules → JS names, `wasm` panics and type expressions → package scope → incremental builds (after `go-embed` too) → JS dead-code elimination.
- *`wasm` backend:* `wasm` struct types → value stores (its Phase 4 needs struct types Phase 1).
- *Web:* typed web platform (after checker Go rules) → `gom` signals.

`gofront check` reports every package and `//go:embed` are independent and can land any time (`go-embed` before incremental builds). Shared file: `mangleLocalTypes` (`src/compiler.js`) is changed by checker Go rules Task 8.1 and names/panics Task 1.3, so whichever lands second rebases.

## v1.8.0

**Theme: Portable Go & The Great Simplification.** Make GoFront complete, clean, and lean inside its no-runtime and JS/WASM boundaries. Language additions include range-over-func, generic named func types and type aliases, complex numbers, `min`/`max`, predeclared name shadowing, and modern iterators (`iter`, `slices`, `maps`). Compile-time `encoding/json` works on both backends. The release finishes with **The Great Simplification** (Phases 8–11): retiring the 377 KB coverage manifest and real-Go conformance runner, pruning the stdlib to a lean core (`bufio`, `net/url`, `context`, `encoding/csv`, `container/*` and most of the new pure packages go), and removing WASM workarounds (scalar interior-pointer accessors, array clone elision) in favor of a clear compile-time diagnostic. Design document in [`plans/v1.8.0/portable-go-plan.md`](v1.8.0/portable-go-plan.md).

## Out of scope

Goroutines, channels, `select`, `unsafe`, full `reflect`, `cgo`, exact integer overflow,
Go-equivalent map semantics. These all require either a runtime scheduler or memory model
that conflicts with the "no runtime" principle.

`goto` — no clean JS translation in the general case (cross-scope jumps require a
runtime scheduler equivalent). See README § What's not implemented for the full list.
