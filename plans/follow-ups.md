- **WASM struct assignment:** `v = w` of a struct with an embedded struct field shares the embedded value when `v` is captured by a closure. Repro: `v := V{P{-4}, 7}; w := v; f := func() { v.M = 5 }; v = w; f(); fmt.Println(w, v)` (V embeds P) → wasm got `{{5} 7} {{5} 7}`, want `{{-4} 7} {{5} 7}`. (feat/assignment-semantics-phase-1, assignment-semantics Phase 1, Out of Scope)
- **Fuzzer transitive mutations:** `stmtConflicts` does not follow `ks(...)` calls inside closure bodies, so a statement can still depend on read-vs-call order. Repro: `node test/fuzz/difffuzz.js --mode order --stmts 12 --case 6873:0` → `xs[(f1(-4))&1] = ((a / 3) * -1)` passes `stmtConflicts`, want it regenerated. (PR #219, assignment-semantics Phase 1, Low)
- **Fuzzer closure order:** `f0`–`f2` are declared before `ks` but may call it, so the batch is rejected by Go. Repro: `node test/fuzz/difffuzz.js --mode order --stmts 12 --case 6873:0` → got `Undefined: 'ks'`, want a valid Go program. (PR #219, assignment-semantics Phase 1, Out of Scope)
- **Multi-assignment (non-Ident targets):** `lhsOperandBinds` only tracks `Ident` targets as assigned, so an operand mentioning a field or element target assigned in the same statement is read after the first store. Repro: `type SP struct{ P *int }; sa, sb := 1, 2; sp := SP{P: &sa}; sp.P, *sp.P = &sb, 99; fmt.Println(sa, sb)` → got `1 99`, want `99 2` (also `xs[0], *xs[0] = &xb, 99`). (PR #220, assignment-semantics Phase 2, Out of Scope)
- **JS range-over-func assign form:** `for *p = range seq`, `for s = range seq` with `&s` taken, and `for arr = range seq` with `arr[:]` aliased do not store in place on `js`/`both`. Repro: `s := S{1}; p := &s; seq := func(yield func(S) bool) { yield(S{5}) }; for *p = range seq {}` → got `Invalid left-hand side in assignment`, want `{5}`; `for s = range seq {}` with `ps := &s` → got `{1} false`, want `{2} true`. (PR #221, assignment-semantics Phase 3, Out of Scope)
- **Comma-ok into an address-taken struct:** `s, ok = m["k"]` and `s, ok = i.(S)` replace the variable instead of copying in place, so earlier pointers go stale on all targets. Repro: `s := S{1}; ps := &s; m := map[string]S{"k": {5}}; var ok bool; s, ok = m["k"]; fmt.Println(*ps, ps == &s)` → got `{1} false`, want `{5} true`. (PR #221, assignment-semantics Phase 3, Out of Scope)
- **JS comma-ok into a generic `*T`:** `func f[T any](p *T, m map[string]T) { var ok bool; *p, ok = m["k"] }` crashes on `js`/`both`. Repro: call `f(&S{1}, map[string]S{"k": {5}})` → got `Invalid left-hand side in assignment`, want `{5} true`. (PR #221, assignment-semantics Phase 3, Out of Scope)
- **JS complex compound assignment:** a call in the left-hand target with a call-free right-hand side runs three times, a `for` post `c += z` yields NaN, and `c += f()` on an address-taken `c` crashes. Repro: `m := map[string]complex128{"a": complex(1, 2)}; m[k()] += z` → got `k()` called 3 times on `js`/`both`, want 1; `for i := 0; i < 2; c += z { i++ }` → got `(NaN+NaNi)`, want `(2+2i)`; `p := &c; c += f()` → got `Cannot read properties of undefined (reading 're')`. (PR #222, assignment-semantics Phase 4, Out of Scope)
- **JS comma-ok `:=` in a `for` initializer:** `for v, ok := m[k()]; ok; ok = false {}` crashes on `js`/`both`. Repro: `for v, ok := m[k()]; ok; ok = false { fmt.Println(v, ok, n) }` → got `number 5 is not iterable`, want `5 true 1`. (PR #222, assignment-semantics Phase 4, Out of Scope)
- **WASM struct literal into a struct holding a value-struct field:** the field is shared, not copied. Repro: `type P struct{ A [2]int }; type W struct{ Q P }; p := P{[2]int{1, 2}}; var a W; pa := &a; *pa = W{Q: p}; pa.Q.A[0] = 9; fmt.Println(p, a)` → got `{[9 2]} {{[9 2]}}`, want `{[1 2]} {{[9 2]}}`. (PR #222, assignment-semantics Phase 4, Out of Scope)
