# Follow-ups

Bugs noticed outside the task at hand, each with a repro so it can be re-checked later. Written by `/dev-loop` reviewers and by any agent session. Open items only: `/design-plan follow-ups` re-probes them, groups them by root cause, and moves each into a plan (as a fix task or a deferred row), deleting it here.

Each entry names its root cause (the mechanism that produces it, not the path that exposed it) and its route: the open plan whose scope covers that root, or `unrouted`. Entries with the same root sit together. A defect with the same root as the task being fixed is part of that task and never lands here (`/dev-loop` **Follow-ups**).

- **JS discarded map literal:** a discarded map literal with computed keys is emitted as a statement starting with `{`. Root: `js-stmt-expr-start` (expression statements are not parenthesised when they begin with `{`). Repro: `func main() { _ = map[any]int{1: 1} }` on `js` → got `SyntaxError: Unexpected token ':'`, want it to run. (checker-strictness Phase 6, Out of Scope; re-probed 2026-11-17) → unrouted
- **wasm type switch:** a case on a defined empty interface does not match on wasm. Root: `wasm-typeswitch-empty-iface` (wasm type-switch matching against defined empty interface). Repro: `type B interface{}; var x any = B(1); switch v := x.(type) { case B: fmt.Println(v) }` → got `` on wasm, want `1`. (PR #236, checker-go-rules Phase 3, Out of Scope) → unrouted
- **Condition messages:** `if v` / `for v` on a defined empty interface report `If condition must be bool` rather than Go's `non-boolean condition`. Root: `empty-interface-kinds` (`statements.js:_checkIfStmt`, `_checkForCond`, `assignability.js:_checkIfaceToConcrete` test `._declared`). Repro: `type MyAny any; var v MyAny = true; if v {}` → got `If condition must be bool`, want `non-boolean condition in if statement`. (PR #236, checker-go-rules Phase 3, Low) → checker-go-rules
- **Builtin arity:** builtins do not validate argument counts. Root: `builtin-arg-count` (`src/typechecker/expressions.js:BUILTIN_CHECK` never checks `expr.args.length`). Repro: `func main() { clear() }` → got `InternalCompilerError` on all targets, want `not enough arguments for clear() (expected 1, found 0)`. (PR #237, checker-go-rules Phase 4, Out of Scope) → unrouted
- **min/max unification:** `min`/`max` arguments are not unified to one type. Root: `minmax-type-unification` (`expressions.js:_checkMinMax`/`minMaxType` pick the first typed operand and skip `convertUntyped`). Repro: `_ = min(1, "a")` → got compiled on both / ICE on wasm, want `mismatched types untyped int and untyped string`. (PR #237, checker-go-rules Phase 4, Out of Scope) → unrouted
- **Spread to non-variadic:** `f(xs...)` on a non-variadic function is accepted. Root: `spread-non-variadic` (`expressions.js:_checkCallArgs` ignores `_spread` when `!fnType.variadic`). Repro: `func f(xs []int) {}; f([]int{1}...)` → got accepted, want `cannot use ... in call to non-variadic f`. (PR #237, checker-go-rules Phase 4, Out of Scope) → unrouted
- **Builtins on type parameters:** builtins return early for type parameters without checking the constraint. Root: `builtin-type-param-constraints` (`expressions.js:_lenOperandOk`, `_appendOperandOk`, `_checkDeleteOperand`, `_checkClearOperand`, `_orderedOperandOk` skip `typeParam`). Repro: `func f[T any](v T) int { return len(v) }` → got accepted, want `invalid argument: v … for built-in len`. (PR #237, checker-go-rules Phase 4, Out of Scope) → checker-go-rules
- **copy on defined slices:** `copy` element check unwraps only one named level. Root: `ad-hoc-type-structure` (`expressions.js:_checkBuiltinCopy` `elemOf`). Repro: `type S1 []int; type S2 S1; copy(S2{1}, []string{"a"})` → got accepted, want element mismatch error. (PR #237, checker-go-rules Phase 4, Out of Scope) → checker-go-rules
- **Package functions:** an exported package function is assignable and addressable. Root: `addressability` (`src/typechecker/expressions.js:_isAddressableSelector` cannot tell package `func` declarations from `func`-typed package vars; needs function names on namespace objects across `src/compiler.js`, `src/link/stdlib.js`). Repro: `import "fmt"; func main() { fmt.Println = nil }` → got accepted, want `cannot assign to fmt.Println (neither addressable nor a map index expression)`. (PR #238, checker-go-rules Phase 5, Out of Scope) → checker-go-rules
- **Field access on type parameter:** fields are accessible through a type parameter with a struct core type. Root: `type-param-field-access` (`src/typechecker/resolve.js:fieldType`). Repro: `func f[T ~struct{ X int }](mk func() T) { mk().X = 1 }` → got accepted, want `mk().X undefined (type T has no field or method X)`. (PR #238, checker-go-rules Phase 5, Out of Scope) → unrouted
- **Assignment diagnostics text:** unaddressable-assignment messages print `expression[0]` / `expression.X` for literals and type assertions instead of the source text; the fixtures only pass because the message embeds the `// ERROR` source line. Root: `operand-text` (`src/typechecker/operand-text.js:exprText`). Repro: `[2]int{1, 2}[0] = 3` → got `cannot assign to expression[0] …`, want `cannot assign to [2]int{…}[0] …`. (PR #238, checker-go-rules Phase 5, Low) → unrouted
- **Package-qualified type names:** a type reached through a package qualifier is assignable and addressable. Root: `addressability` (`src/typechecker/expressions.js:_isAddressableSelector` returns true for any non-const namespace member and ignores `_isTypeRef`; `src/dts-parser.js:_parseMember` stores nested `.d.ts` class/namespace members as kind `namespace` without registering a type). Repro: `import "strings"; func main() { strings.Builder = strings.Builder{}; _ = &strings.Builder }` → got accepted on `js`, `InternalCompilerError` on `wasm`, want `cannot assign to strings.Builder (neither addressable nor a map index expression)`. Same for `shared.Float32`, `simd.F32x4`, a local-package `sub.Box`, `.d.ts` `NS.Inner`. (PR #238, checker-go-rules Phase 5, High) → checker-go-rules
- **Function-local types leak:** a type declared inside a function is visible package-wide. Root: `local-type-scope` (`src/typechecker/index.js:_defineTypeBinding` binds the local type in `this.globals` and `this.types`, and overwrites a dot-imported package variable's type in `globals.symbols`). Repro: `func f() { type Q struct{ X int } }; func main() { var q Q; _ = q }` → got accepted, want `undefined: Q`; also `import . "./sub"` (`var Q int`) with a local `type Q` in a function → got `Cannot assign untyped int to Q`. (PR #238, checker-go-rules Phase 5, Medium) → unrouted
- **Dot-imported functions:** a dot-imported declared function is assignable. Root: `addressability` (`src/typechecker/index.js:addDefinitions` does not record dot-imported function names in `_funcDeclNames`, which `_isAddressableIdent` reads). Repro: `import . "./sub"` (`func Fn() {}`) then `func main() { Fn = nil }` → got accepted on `js` and `wasm`, want `cannot assign to Fn (neither addressable nor a map index expression)`. Also `simd.NewF32x4 = nil`, same root as Package functions. (PR #238, checker-go-rules Phase 5, Medium) → checker-go-rules
