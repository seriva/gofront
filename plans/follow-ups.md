- **WASM imports:** A package used only in a constant array length is reported as unused on the wasm target. Repro: `package main; import ("fmt"; "math"); func main() { var a [math.MaxInt8]int; fmt.Println(len(a)) }` compiled with `forceTarget: "wasm"` → got `'math' imported and not used`, want `127`. (feat/follow-ups-2026-11-09-phase-1, follow-ups-2026-11-09 Phase 1, Out of Scope)
- **Typechecker:** `switch true { case nil: }` is accepted and emits invalid WASM. Repro: `package main; func main() { switch true { case nil: } }` on the wasm target → got `i32.eq[1] expected type i32, found ref.null of type anyref`, want `cannot convert nil to type bool`. (PR #164, follow-ups-2026-11-09 Phase 1, Out of Scope)
- **Typechecker:** `cap` accepts struct and func operands and emits invalid WASM. Repro: `package main; func main() { type S struct{}; var s S; _ = cap(s) }` on the wasm target → got `not enough arguments on the stack for i64.extend_i32_u`, want `invalid argument: s (variable of type S) for cap`. (PR #164, follow-ups-2026-11-09 Phase 1, Out of Scope)
- **Typechecker:** An explicit conversion of a concrete value to an interface type is rejected, and the `interface{ M() }(v)` literal form does not parse. Repro: `type I interface{ M() }; type T struct{}; func (T) M() {}; func main() { _ = I(T{}) }` → got `cannot convert T to I`, want it to compile. (feat/follow-ups-2026-11-09-phase-2, follow-ups-2026-11-09 Phase 2, Out of Scope)
- **Typechecker:** `any` is assignable to a non-empty interface without a type assertion. Repro: `package main; func main() { var b any; var e error; e = b; _ = e }` → got no error, want `cannot use b (variable of type any) as error value in assignment: need type assertion`. (PR #165, follow-ups-2026-11-09 Phase 2, Out of Scope)
- **Typechecker:** A constraint interface (type-set element) is accepted as an ordinary variable type. Repro: `type N interface{ ~int | ~string }; func main() { var x N; _ = x }` → got no error, want `cannot use type N outside a type constraint`. (feat/follow-ups-2026-11-09-phase-3, follow-ups-2026-11-09 Phase 3, Out of Scope)
- **JS backend:** A 64-bit compound assignment with an untyped constant in a `for` post statement fails at runtime. Repro: `package main; import "fmt"; const half = 1 << 51; func main() { var b uint64 = 1; for i := 0; i < 1; b += half { i++ }; fmt.Println(b) }` on js → got `TypeError: Cannot mix BigInt and other types`, want `2251799813685249`. (PR #166, follow-ups-2026-11-09 Phase 3, Out of Scope)
- **JS backend:** `continue outer` from a nested range-over-func loop to an outer range-over-func label emits an undefined label. Repro: `outer: for x := range seq { for y := range seq { continue outer } }` on js → got `SyntaxError: Undefined label 'outer'`, want it to run. (PR #166, follow-ups-2026-11-09 Phase 3, Out of Scope) (PR #167, follow-ups-2026-11-09 Phase 4; also stops early on WASM)
- **WASM backend:** Range assignment into an address-taken variable over a slice or string emits invalid WASM. Repro: `s := []int{10, 20}; var v int; p := &v; for _, v = range s {}; fmt.Println(*p)` on wasm → got `local.set[0] expected type (ref null ...), found array.get of type i64`, want `20`. (PR #167, follow-ups-2026-11-09 Phase 4, Out of Scope)
- **WASM backend:** Interface method dispatch on a boxed struct whose method is promoted through an embedded pointer panics. Repro: `type Mer interface{ M() string }; type Inner struct{}; func (i *Inner) M() string { return "inner" }; type PO struct{ *Inner }; var v any = PO{&Inner{}}; m, ok := v.(Mer); if ok { fmt.Println(m.M()) }` on wasm → got `panic: interface conversion: nil or unmatched type for method call`, want `inner`. (PR #167, follow-ups-2026-11-09 Phase 4, Out of Scope)
- **JS nil receivers:** A method whose receiver name is shadowed by an inner variable that reads a field is treated as dereferencing the receiver, so calling it on a nil pointer throws. Repro: `type Other struct{ val int }; type S struct{ x int }; func (s *S) M() int { if true { s := &Other{val: 5}; return s.val }; return 0 }; func main() { var s *S; fmt.Println(s.M()) }` on js → got `TypeError: Cannot read properties of null (reading 'M')`, want `5`. (PR #168, follow-ups-2026-11-09 Phase 5, Low)
- **JS nil receivers:** A pointer-receiver method that reads through its receiver on only some paths (no nil comparison) still throws on a nil pointer in JS. Repro: `func (s *S) M() int { if cond { return s.x }; return 0 }` called on `var s *S` with `cond` false → got `TypeError`, want `0`. (PR #168, follow-ups-2026-11-09 Phase 5, Low)
- **JS nil receivers:** Methods on nil pointers to generic structs keep direct calls and throw. Repro: `type Gen[T any] struct{ val T }; func (g *Gen[T]) Ping() string { if g == nil { return "nil" }; return "ok" }; func main() { var g *Gen[int]; fmt.Println(g.Ping()) }` on js → got `TypeError: Cannot read properties of null (reading 'Ping')`, want `nil`. (PR #168, follow-ups-2026-11-09 Phase 5, Out of Scope)
- **JS method expressions:** `(*S).ValueMethod` called with a nil pointer runs instead of panicking. Repro: `type S struct{ x int }; func (s S) V() int { return 10 }; func main() { f := (*S).V; var s *S; fmt.Println(f(s)) }` on js → got `10`, want `runtime error: invalid memory address or nil pointer dereference`. (PR #168, follow-ups-2026-11-09 Phase 5, Out of Scope)
- **JS map keys:** A defined slice or map literal used directly as a `map[any]` key does not panic. Repro: `type L []int; func main() { m := map[any]int{}; m[L{1}] = 1; fmt.Println("no panic") }` on js → got `no panic`, want `runtime error: hash of unhashable type main.L`. (PR #168, follow-ups-2026-11-09 Phase 5, Out of Scope)
- **WASM map keys:** The unhashable-key panic for a defined map type names the underlying type. Repro: `type M map[string]int; func try(k any) { defer func() { fmt.Println(recover()) }(); m := map[any]int{}; m[k] = 1 }; func main() { try(M{}) }` on wasm → got `hash of unhashable type map[string]int`, want `hash of unhashable type main.M`. (PR #168, follow-ups-2026-11-09 Phase 5, Out of Scope)
- **Parser:** A composite literal of a func-element slice as a call argument fails to parse. Repro: `func show(v any) {}; func main() { show([]func(){nil}) }` → got `Parse error at 4:15: expected ')' (got { "{")`, want it to compile (the same literal assigned with `:=` parses). (feat/follow-ups-2026-11-09-phase-6, follow-ups-2026-11-09 Phase 6, Out of Scope)
- **JS json:** `json.Marshal` of an array of funcs in `any` encodes `null` elements on JS instead of failing. Repro: `var a [2]func(); var v any = a; b, err := json.Marshal(v); fmt.Println(string(b), err)` on js → got `[null,null] <nil>`, want ` json: unsupported type: func()`. (PR #169, follow-ups-2026-11-09 Phase 6, Out of Scope)
