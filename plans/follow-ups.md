- **Typechecker/JS promoted selectors:** A method promoted at a shallower depth than a same-named field is not selected: the flattened field map wins in the typechecker and the JS class keeps the field as an instance property over the stub method. Repro: `type In struct{ M int }; type A struct{ In }; type B struct{}; func (B) M() string { return "m" }; type C struct{ A; B }; fmt.Println(C{}.M())` → got `Cannot call non-function type int`, want `m`. (feat/follow-ups-2026-11-11b-phase-1, follow-ups-2026-11-11b Phase 1, Out of Scope)
- **WASM boundary:** An exported struct with an exported interface field whose method returns multiple values cannot compile in a `both` package, because tuple returns in interface methods are not supported across the wasm boundary facade. Repro: `type Pairer interface { Pair(int) (int, string) }; type S struct { P Pairer }; func main() {}` with `forceTarget: "both"` → got `WASM compile failed: S.P: type kind 'tuple' (in method Pairer.Pair) is not yet supported across the wasm boundary (planned)`, want successful compilation. (PR #186, follow-ups-2026-11-11b Phase 2, Out of Scope)
- **WASM array identity:** Unnamed arrays whose element types share a wasm representation and length are one type in an `any` (`[2]int` and `[2]int64`, `[2]A` and `[2][2]int`). Repro: `var w any = [2]int64{}; _, ok := w.([2]int); fmt.Println(ok)` (wasm) → got `true`, want `false`. (feat/follow-ups-2026-11-11b-phase-3, follow-ups-2026-11-11b Phase 3, Out of Scope)
- **Generic `%T` of funcs:** `%T` of a slice built from a func type argument with a variadic parameter and several results prints nothing on both JS and WASM. Repro: `func mk[V any](v V) any { return []V{v} }; fmt.Printf("%T\n", mk(func(a int, b ...string) (int, error) { return 0, nil }))` → got empty line, want `[]func(int, ...string) (int, error)`. (feat/follow-ups-2026-11-11b-phase-3, follow-ups-2026-11-11b Phase 3, Out of Scope)
- **Untyped constants as complex values:** An untyped constant passed to `append` for a `[]complex128` is emitted as a plain number in `js` and `both` packages. Repro: `var c []complex128; c = append(c, 7); fmt.Println(c)` → got `[(NaN+NaNi)]` (js), want `[(7+0i)]`. (feat/follow-ups-2026-11-11b-phase-4, follow-ups-2026-11-11b Phase 4, Out of Scope)
- **WASM untyped complex constants:** Three forms that take an untyped constant where a `complex128` is expected build an invalid module or fail to type-check in a `wasm` package. Repro: `var c complex128; p := &c; *p = 9` and `var c complex128 = 2; switch c { case 2: }` → got `WebAssembly.validate failed` (`not enough arguments on the stack`), and `func p(z complex128) {}; defer p(2)` → got `Cannot assign int to complex128`, want all three to compile and run as in Go. (feat/follow-ups-2026-11-11b-phase-4, follow-ups-2026-11-11b Phase 4, Out of Scope)
- **JS range assignment into an interface:** `for _, s = range xs` into a `fmt.Stringer` does not wrap an element of a defined non-struct type with methods, so its methods are lost. Repro: `type N int; func (n N) String() string { return fmt.Sprintf("N%d", int(n)) }; var s fmt.Stringer; for _, s = range []N{3, 4} {}; fmt.Println(s)` → got `4` (js), want `N4` (`s = N(4)` prints `N4`). (feat/follow-ups-2026-11-11b-phase-4, follow-ups-2026-11-11b Phase 4, Out of Scope)
