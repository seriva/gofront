- **JS type switch:** a `case func():` (or any func-type case) on an `any` always matches in JS because the check is emitted as `if (true)`, so non-func values and funcs of other signatures take that case. Repro: `switch x.(type) { case func(): return "f"; default: return "d" }` with `kind(1)` and `kind(func(int) string {...})` → got `f f` on js/both, want `d d` (wasm prints `d`). (feat/follow-ups-2026-11-03-phase-1, follow-ups-2026-11-03 Phase 1, Out of Scope)
- **WASM pointer conversion:** `(*S)(&b)` between two struct types with identical fields (`type S Base`) is rejected in wasm and both packages because WebAssembly struct types are nominal and the two pointers cannot share one object. Repro: `type Base struct{n int}; type S Base; b := Base{1}; p := (*S)(&b)` in a `//gofront:target both` package → got `cannot convert *Base to *S in a wasm package`, want compiles and `p.n` aliases `b.n`. (feat/follow-ups-2026-11-03-phase-2, follow-ups-2026-11-03 Phase 2, Out of Scope)
- **JS pointer conversion:** a method called through a pointer converted to another struct type fails because the object keeps the source type's class. Repro: `type Base struct{n int}; type S Base; func (s *S) Inc() { s.n++ }; b := Base{1}; (*S)(&b).Inc()` → got `p.Inc is not a function`, want `b.n == 2`. (feat/follow-ups-2026-11-03-phase-2, follow-ups-2026-11-03 Phase 2, Out of Scope)
- **JS comma-ok define boxing:** an address-taken variable bound by a comma-ok map read is never boxed, so writing through the pointer throws. Repro: `m := map[string]int{"k": 3}; x, y := m["k"]; p := &x; *p = 9; println(x, y)` → got `Cannot create property 'value' on number '3'`, want `9 true`. (feat/follow-ups-2026-11-03-phase-2, follow-ups-2026-11-03 Phase 2, Out of Scope)
