- **Logical operators on defined bool operands:** `&&` and `||` of two operands of a defined bool type yield `bool`, not that type, so assigning the result to it is rejected. Repro: `type B bool; var b1, b2 B; var b3 B = b1 && b2` → got `Type error … Cannot assign bool to B`, want it to compile. (PR #194, follow-ups-2026-11-12 Phase 10, Out of Scope)
- **Non-integer array length:** A constant boolean expression is accepted as an array length, and the JavaScript output is then a syntax error. Repro: `var arr [1 == 1]int; fmt.Println(len(arr))` → got `SyntaxError: Unexpected identifier 'Object'` (js), want a compile-time type error rejecting the non-integer array bound. (PR #194, follow-ups-2026-11-12 Phase 10, Out of Scope)
- **`%T` of a map with `bool` or small-integer keys holding funcs:** a map whose key is a `bool` or an integer of at most 32 bits and whose value is a func prints an empty `%T` when boxed into an `any`. Repro: `var a any = map[bool]func(){}; fmt.Printf("%T\n", a)` → got an empty line on every target, want `map[bool]func()`. (feat/follow-ups-2026-11-12-phase-11, follow-ups-2026-11-12 Phase 11, Out of Scope)
- **JS type tag lost when generic code boxes a map:** A map that generic code returns as `any` loses its non-enumerable type tag in JavaScript, so `fmt` formats it as the wrong map type. Repro: `func gen[T any](v T) any { return v }; m1 := gen(map[string]bool{"a": true}); m2 := gen(map[string]int{"a": 1}); fmt.Printf("%T|%v\n", m1, m1)` → got `map[string]int|map[a:-9223372036854775808]` (js), want `map[string]bool|map[a:true]`. (PR #195, follow-ups-2026-11-12 Phase 11, Out of Scope)
- **Range-over-func assignment is not checked for assignability:** A range-over-func loop assigns its yielded value to any target without checking the target's type. Repro: `func seq(yield func(int) bool) { yield(1) }; var s string; for s = range seq {}` → got no error on any target, want `Cannot assign int to string`. (PR #195, follow-ups-2026-11-12 Phase 11, Out of Scope)
